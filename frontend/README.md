# Панель операторов (Vue)

Единственная панель на Vue 3, TypeScript, Vite, Tailwind CSS 4, Pinia и Reka UI, доступная по
`/console/`. Перенесены операторский флоу (вход, выбор проекта, список диалогов с поиском, архивом и
папками, переписка, ответы, live-обновления) и администрирование: проекты (подключения, участники,
логотип), сотрудники установки (Telegram ID, сброс пароля, передача установки) и смена своего пароля.

Нужен Node.js 24. Сборка пишет в `src/resolvate/console_dist/` (каталог в `.gitignore`). Образ Docker
собирает её сам в стадии `frontend`.

```bash
npm ci --ignore-scripts
npm run dev       # Vite на :5173, API проксируется на установку на :8080 (CONSOLE_ORIGIN=http://localhost:8080)
npm run build     # production-сборка в ../src/resolvate/console_dist
npm run check     # lockfile, типы, модульные тесты, сборка, проверка под CSP, лицензии
npx playwright test --project=chromium   # браузерные тесты против сборки и заглушки API
```

## Интеграционная проверка с backend

В корне репозитория должны быть установлены Python dev-зависимости в `.venv`, а панель собрана
командой `npm run build`. Для запуска из `frontend/`:

```bash
export TEST_POSTGRES_DATABASE_URL='postgresql+asyncpg://resolvate_test:resolvate-test-only-password@127.0.0.1:5432/resolvate_test'
export ALLOW_POSTGRES_TEST_DATABASE_CREATION=yes
npx playwright install chromium
npx playwright test --config=playwright.integration.config.ts
```

Используйте **только отдельный тестовый кластер**: пользователь должен уметь создавать БД и роли.
Сервер привязан к `127.0.0.1:4174` (`CONSOLE_TEST_PORT` меняет порт), отказывается использовать
чужую работающую установку и создаёт/удаляет собственные временные БД, роли и файлы. Production `.env`
не читается. Runtime подключается ограниченной ролью без SUPERUSER/BYPASSRLS и проходит штатную
проверку RLS. HTTP, cookie, CSRF, маршруты установки/проектов и данные настоящие, не перехваченные
ответы Playwright. Проверяются вход, отправка ответа в очередь и сохранение истории после reload,
выход, создание сотрудника/проекта, настоящая multipart-загрузка изображения с просмотром после
reload и отказы по правам/CSRF.

Граница проверки: проектные HTTP-приложения подключены через штатный ProjectRouter, но Telegram
polling, внешние интеграции и фоновые доставки не запускаются. Факт доставки клиенту Telegram,
перезапуск ProjectManager и полный контейнерный запуск этим тестом не проверяются. Существующие
unit/PostgreSQL-тесты и smoke-проверка Docker-образа дополняют его, а не заменяются им.

В CI обычные браузерные тесты разделены на два jobs с отдельными заглушками и `workers: 1`.
Не запускайте параллельные tests против одного stub: его сценарий общий для всего процесса.

## Структура `src/`

- `api/` — клиент API панели и типы ответов. Любой сбой запроса — `ApiError` с текстом для оператора;
  запрос, отменённый вызывающим кодом, отклоняется как отменённый.
- `stores/` — общее состояние (Pinia): `session`, `theme`, `projects` (проекты, текущий, состояние
  загрузки и изменения администраторов), `tickets` (список, поиск, архив, фильтр папки, страницы),
  `folders`, `chat` (открытый диалог, история, черновики, кэш, отправка), `staff` (аккаунты установки),
  `workspace` (уведомления, «список или диалог» на узком экране, открытое окно администрирования,
  первая загрузка и цикл обновления).
- `composables/` — механика браузера и UI без собственного доменного состояния: `useLiveUpdates` (поток
  событий проекта, опрос, видимость вкладки), `useSidebarResize`, `useImageGestures`, `useColorScheme`,
  `useRequest` (изменение из формы: одно за раз, ответ сервера, блокировка окна на время запроса).
- `components/<домен>/` — экраны и их части: `auth/`, `workspace/` (каркас, шапка, меню «Управление»,
  разделитель), `projects/` (выбор проекта, пустые состояния, окно «Проекты», участники, подключения),
  `staff/` (окно «Сотрудники», поиск сотрудника), `tickets/` (колонка и список), `folders/` (вкладки,
  окна папок, папка диалога),
  `chat/` (диалог: шапка, карточка клиента, история, сообщения, вложения, стикеры, просмотр фото),
  `composer/` (ответ и готовые ответы), `account/` (меню аккаунта, тема, окно пароля). Новый домен — новая
  папка с его первым экраном.
- `components/ui/` — общие примитивы без доменной логики: `Icon`, `IconButton` (Tooltip),
  `ModalDialog` (Dialog), `ConfirmDialog` (AlertDialog), `MenuSelect` (выбор из списка), `ActionMenu`
  (меню «⋯» действий одного элемента, DropdownMenu).
- `lib/` — чистые функции, `boot/` — скрипт темы до первой отрисовки, `styles/` — Tailwind и токены.

## UI-примитивы

- Нативные `button`, `input`, `textarea`, `form` и `label` остаются нативными, оформление — в
  `styles/app.css`. Обёртка в `components/ui/` нужна, когда повторяется поведение, а не разметка.
- Составные контролы — на Reka UI: она даёт клавиатуру, фокус и ARIA. Подписи кнопок-иконок —
  Tooltip (`ui/IconButton`); окна — Dialog (`ui/ModalDialog`, просмотр фото); выбор проекта и папки
  диалога — DropdownMenu с RadioGroup (`ui/MenuSelect`); вкладки папок — Tabs; список диалогов — Listbox
  (одна остановка Tab, стрелки, Home/End, поиск по буквам). Готовые ответы — свой лёгкий список при поле
  ответа: фокус остаётся в поле, активный вариант — `aria-activedescendant`. В окне каталога ответов
  (`composer/ReplyCatalog`) группы — Listbox, действия группы и ответа — `ui/ActionMenu`.
  Подтверждения — AlertDialog (`ui/ConfirmDialog`), вкладки проекта — Tabs. Поиск сотрудника — Combobox
  (`staff/StaffPicker`) без `ComboboxViewport`: список ищет на сервере или в загруженном списке, первый
  ответ подсвечен.
- Окна администрирования загружаются отдельными чанками только при открытии: у операторов их кода
  нет в основном бандле. Если чанк не загрузился (старая вкладка после обновления), окно закрывается
  с уведомлением, а рабочее место и черновики остаются: экран «Не удалось загрузить панель» в
  `main.ts` показывается только до старта приложения.
- Окно, открытое из меню, открывается после того, как меню вернуло фокус на свою кнопку: Reka
  возвращает его только по таймеру, и раньше открытое окно запомнило бы исчезающий пункт меню.
- Listbox Reka сам переводит фокус на значение, выбранное из кода (новая группа каталога, группа из
  результатов поиска), через несколько микрозадач после отрисовки. Фокус после такого выбора ставится
  следующей задачей (`setTimeout`), иначе Listbox заберёт его себе.
- В reka-ui 2.11.0 Tooltip вокруг DropdownMenuTrigger (и наоборот) лишает меню опорного элемента:
  у кнопки меню «Управление» на узком экране подпись — свой скрытый элемент, показанный CSS.
- Кнопка, которая ждёт ответа сервера, получает `aria-disabled="true"` и игнорирует повторное нажатие:
  атрибут `disabled` сбросил бы фокус клавиатуры.
- Когда один экран сменяет другой, фокус переходит на его заголовок или первое поле.
- Поведение проверяют `e2e/a11y.spec.ts`, `e2e/operator.spec.ts`, `e2e/catalog.spec.ts`, `e2e/admin.spec.ts`
  и `e2e/passwords.spec.ts` на production-сборке под CSP панели:
  клавиатура (Tab, Enter, пробел, Esc, стрелки), фокус, роли и имена для скринридера, отсутствие нарушений
  CSP и ошибок в консоли. API в них отвечает `e2e/stub/api.mjs` — те же пути и формы ответов, что у
  backend, с дельтами по ревизиям, курсором истории, ревизиями папок и потоком событий; маршруты
  установки (аккаунты, пароли, проекты, участники, подключения, логотипы) — `e2e/stub/admin.mjs` с теми
  же правами, правилами и ответами, что у backend.

## Ограничения

- CSP панели не ослабляется (`src/resolvate/console.py`): `script-src 'self'`, `style-src 'self'`, без
  `unsafe-inline`, `data:` и `blob:`. Статические атрибуты `style="…"` в шаблонах, `v-html`, блоки
  `<style>` в компонентах и строковые `:style` запрещены тестом `src/templates.test.ts`. Динамический
  `:style` объектом допустим: Vue применяет его через CSSOM.
- Компоненты Reka UI, которые вставляют `<style>` (в reka-ui 2.11.0 — viewport у Select, Combobox и
  ScrollArea, а также `Viewport`), не используются: CSP их блокирует, а ослаблять её ради оформления
  нельзя (`docs/DESIGN.md`).
- Тема применяется скриптом `src/boot/theme-boot.js` до первой отрисовки, для экрана входа и панели
  одинаково. Ключ `localStorage` — `resolvate.theme` (сохранённые настройки совместимы).
- Минимальные браузеры (Tailwind CSS 4): Safari 16.4, Chrome 111, Firefox 128.

Браузерные тесты локально удобнее запускать в образе `mcr.microsoft.com/playwright:v1.63.0-noble`:
он уже содержит Chromium, Firefox и WebKit.
