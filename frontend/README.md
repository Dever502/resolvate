# Панель операторов (Vue)

Единственная панель на Vue 3, TypeScript, Vite, Tailwind CSS 4, Pinia и Reka UI, доступная по
`/console/`. Перенесены операторский флоу (вход, выбор проекта, список диалогов с поиском, архивом и
папками, переписка, ответы, live-обновления) и администрирование: проекты (подключения, участники,
логотип), сотрудники установки (Telegram ID, сброс пароля, передача установки) и смена своего пароля.

Нужен Node.js 24. Сборка пишет в `src/resolvate/console_dist/` (каталог в `.gitignore`). Образ Docker
собирает её сам в стадии `frontend`.

```bash
npm ci --ignore-scripts
npm run dev       # Vite на :5173, API проксируется на установку на :8080 (CONSOLE_ORIGIN=http://localhost:8080)
npm run build     # production-сборка в ../src/resolvate/console_dist
npm run check     # lockfile, типы, модульные тесты, сборка, проверка под CSP, лицензии
npx playwright test --project=chromium   # браузерные тесты против сборки и заглушки API
```

## Интеграционная проверка с backend

В корне репозитория должны быть установлены Python dev-зависимости в `.venv`, а панель собрана
командой `npm run build`. Для запуска из `frontend/`:

```bash
export TEST_POSTGRES_DATABASE_URL='postgresql+asyncpg://resolvate_test:resolvate-test-only-password@127.0.0.1:5432/resolvate_test'
export ALLOW_POSTGRES_TEST_DATABASE_CREATION=yes
npx playwright install chromium
npx playwright test --config=playwright.integration.config.ts
```

Используйте **только отдельный тестовый кластер**: пользователь должен уметь создавать БД и роли.
Сервер привязан к `127.0.0.1:4174` (`CONSOLE_TEST_PORT` меняет порт), отказывается использовать
чужую работающую установку и создаёт/удаляет собственные временные БД, роли и файлы. Production `.env`
не читается. Runtime подключается ограниченной ролью без SUPERUSER/BYPASSRLS и проходит штатную
проверку RLS. HTTP, cookie, CSRF, маршруты установки/проектов и данные настоящие, не перехваченные
ответы Playwright. Проверяются вход, отправка ответа в очередь и сохранение истории после reload,
выход, создание сотрудника/проекта, настоящая multipart-загрузка изображения с просмотром после
reload и отказы по правам/CSRF.

Граница проверки: проектные HTTP-приложения подключены через штатный ProjectRouter, но Telegram
polling, внешние интеграции и фоновые доставки не запускаются. Факт доставки клиенту Telegram,
перезапуск ProjectManager и полный контейнерный запуск этим тестом не проверяются. Существующие
unit/PostgreSQL-тесты и smoke-проверка Docker-образа дополняют его, а не заменяются им.

В CI обычные браузерные тесты разделены на два jobs с отдельными заглушками и `workers: 1`.
Не запускайте параллельные tests против одного stub: его сценарий общий для всего процесса.

## Структура `src/`

- `api/` — клиент API панели и типы ответов. Любой сбой запроса — `ApiError` с текстом для оператора;
  запрос, отменённый вызывающим кодом, отклоняется как отменённый.
- `stores/` — общее состояние (Pinia): `session`, `theme`, `projects` (проекты, текущий, состояние
  загрузки и изменения администраторов), `tickets` (список, поиск, архив, фильтр папки, страницы),
  `folders`, `chat` (открытый диалог, история, черновики, кэш, отправка), `staff` (аккаунты установки),
  `workspace` (уведомления, «список или диалог» на узком экране, открытое окно администрирования,
  первая загрузка и цикл обновления).
- `composables/` — механика браузера и UI без собственного доменного состояния: `useLiveUpdates` (поток
  событий проекта, опрос, видимость вкладки), `useSidebarResize`, `useImageGestures`, `useColorScheme`,
  `useRequest` (изменение из формы: одно за раз, ответ сервера, блокировка окна на время запроса),
  `useNotice` (отклик окна: успех исчезает сам через 3,5 с, предупреждение остаётся до следующего шага),
  `useFileDrop` (файлы, перетащенные на элемент: только перетаскивание с файлами, вложенные элементы, отказ).
- `components/<домен>/` — экраны и их части: `auth/`, `workspace/` (каркас, шапка, меню «Управление»,
  разделитель), `projects/` (выбор проекта, пустые состояния, окно «Проекты», участники, подключения),
  `staff/` (окно «Сотрудники», поиск сотрудника), `tickets/` (колонка и список), `folders/` (вкладки,
  окна папок, папка диалога),
  `chat/` (диалог: шапка, карточка клиента, история, сообщения, вложения, стикеры, просмотр фото),
  `composer/` (ответ и готовые ответы), `account/` (меню аккаунта, тема, окно пароля). Новый домен — новая
  папка с его первым экраном.
- `components/ui/` — общие примитивы без доменной логики: `Icon`, `IconButton` (Tooltip),
  `ModalDialog` (Dialog), `ConfirmDialog` (AlertDialog), `MenuSelect` (выбор из списка), `ActionMenu`
  (меню «⋯» действий одного элемента, DropdownMenu).
- `lib/` — чистые функции, `boot/` — скрипт темы до первой отрисовки, `styles/` — Tailwind и токены.

## Отправка ответа

Черновик (`Draft`: текст и файл) редактируется свободно. Каждое нажатие «Отправить» — отдельная попытка
(`SendAttempt` в `stores/chat.ts`): неизменяемая копия текста и файла с ключом `X-Idempotency-Key`.
Сервер сохраняет сообщение один раз на ключ, на тот же ключ с другим содержимым отвечает 409.

- 2xx — сообщение принято сервером (это не доставка в Telegram: её статус показывает история). Черновик
  очищается, только если он всё ещё равен отправленному. Сбой последующего обновления истории или списка
  не превращает принятую отправку в ошибку.
- 4xx на первый запрос попытки — сервер отказал, ничего не сохранено: попытка закончена, черновик остаётся
  для исправления. Отказ на повторе (429, исчезнувший проект) о первом запросе ничего не говорит: попытка
  остаётся неизвестной.
- Обрыв связи, 5xx или дедлайн (30 с плюс загрузка файла из расчёта 32 КиБ/с) — результат неизвестен:
  попытка остаётся над полем ответа. «Повторить отправку» шлёт ту же копию под тем же ключом; правки
  черновика в неё не попадают, а новый текст не уходит, пока попытка не повторена или не отменена
  («Не повторять»). Попытка закрывается сама, когда её сообщение (поле `command` = ключ) появляется в истории.
- Попытки живут по проекту и диалогу, переживают смену проекта и перезагрузку страницы (см. ниже);
  явный выход из аккаунта их удаляет.

## Перетаскивание файла

Файл, перетащенный на панель диалога (`components/chat/ConversationPanel.vue`, механика —
`composables/useFileDrop.ts`), прикрепляется тем же путём, что и выбранный кнопкой: `chat.attach()` с
правилами `lib/attachment.ts`. Отказ называет причину и не трогает текст и уже прикреплённый файл.
Список диалогов, шапка приложения и окна файлов не принимают.

- Берётся только перетаскивание с файлами (`DataTransfer.types` содержит `Files`); текст и ссылки остаются
  браузеру. Над панелью браузер файл не открывает: `dragenter`, `dragover` и `drop` отменяются, при отказе
  `dropEffect` — `none`.
- Подсветка — рамка с надписью поверх панели (`pointer-events: none`), разметка диалога не меняется. Она
  держится, пока перетаскивание над панелью и её вложенными элементами, и снимается при уходе, отмене,
  drop, смене или закрытии диалога и размонтировании.
- Несколько файлов сразу не прикрепляются (API берёт один файл на ответ): сообщение, ни один не прикреплён.
- Отказ с причиной: нет открытого диалога, открыто модальное окно, диалог недоступен (403/404), черновик
  ещё не прочитан, идёт отправка, диалог сменился во время перетаскивания. Кнопка «Прикрепить файл» и
  системный выбор файла, в том числе на телефоне, не изменились.

## Прочтение и «к последнему сообщению»

Диалог прочитан до сообщения, которое оператор действительно видит. Решает это одно место —
`markLatestVisibleAsRead()` в `components/chat/MessageList.vue`: вкладка видима, панель диалога показана (на
телефоне её может закрывать список), актуальная история загружена (не кэш, пока диалог открывается) и
прокручена до конца. Туда ведут все пути: изменение истории (открытие, новые сообщения при автоследовании),
ручная прокрутка, конец открытия или живого обновления, «к последнему», возврат во вкладку, показ панели
(`ResizeObserver`). Сообщения, пришедшие, пока оператор читает выше, прочитанными не считаются.

- `chat.markRead()` шлёт `POST tickets/{id}/read/{message}` один раз на сообщение и никогда — для сообщения не
  новее подтверждённого или уже отправленного (сервер двигает позицию только вперёд). Неудачная отметка
  повторяется не раньше чем через 5 с, при следующем взгляде на историю, а не на каждое событие прокрутки.
- Сервер не шлёт события на отметку прочтения, поэтому после её подтверждения список диалогов
  синхронизируется сразу (`tickets.sync()`): счётчик непрочитанных приходит с сервера, вместе с тем, что
  успело прийти, без ожидания опроса и без локальных догадок.
- Выбор строки уже открытого диалога (повторный клик, второй клик двойного) не открывает его заново:
  прокрутка и черновик остаются. На телефоне, где диалог закрыт списком, строка показывает его снова у
  последнего сообщения. Двойной клик по строке — сокращение для мыши «к последнему сообщению»
  (`chat.jumpToLatest()`): выполняется, когда история этого диалога загружена и показана; открытие другого
  диалога его отменяет. Клавиатура списка (стрелки, Home/End, Enter, пробел) не меняется.

## Сохранение работы между перезагрузками

Обновление страницы возвращает оператора туда, где он был, и не теряет несохранённую работу:

- `lib/navigation.ts` — то, что вкладка хранит до следующей загрузки, в `sessionStorage` (своё у каждой
  вкладки, живёт, пока жива вкладка): место (`resolvate.workspace`: аккаунт, проект, открытый диалог) и
  тексты черновиков, с которыми страницу покинули до того, как их запись дошла до IndexedDB
  (`resolvate.unsaved`). Ссылка `?project=&ticket=` открывается один раз и уходит из адреса: следующая
  перезагрузка возвращает собственное место вкладки.
- `lib/workStore.ts` — IndexedDB `resolvate-work`, ключ записи — `[account, project, ticket]`: `drafts`
  (текст и описание файла), `files` (байты файла черновика `ArrayBuffer` с именем, типом и датой; пишутся
  только при смене файла) и `attempts` (отправки с неизвестным результатом: ключ, исходные текст и байты
  файла). Файлы хранятся байтами: WebKit в приватном окне не хранит `Blob` в IndexedDB. Истории
  переписки, ответов API и секретов там нет; читается только после проверки сессии.
- Запуск: `workspace.enter()` берёт ссылку или место вкладки, `projects.refresh(true, { preferred })` сразу
  выбирает тот проект (без захода в первый), затем список диалогов и диалог грузятся параллельно.
  Недоступный проект — первый доступный и уведомление; удалённый или запрещённый диалог (403/404) —
  список и уведомление; временный сбой оставляет диалог и черновик. Место пишется наблюдателем в
  собственном `effectScope` стора: после выхода и входа без перезагрузки оно по-прежнему сохраняется.
- Поле ответа доступно для ввода (до того — только чтение), когда черновик диалога прочитан. Перед
  чтением дописываются тексты из `resolvate.unsaved` (если в хранилище нет черновика новее) и записи
  этой вкладки.
- Черновик пишется через 300 мс после правки текста и сразу при смене файла, при уходе из диалога, смене
  проекта, скрытии вкладки (`visibilitychange`, `pagehide`). Записи одного черновика идут по очереди, чтение
  и запись ставятся в одну транзакцию сразу и она фиксируется (`commit()`): старая версия не ложится
  поверх новой. На `pagehide` тексты, чья запись ещё не подтверждена, синхронно кладутся в
  `resolvate.unsaved`: WebKit обрывает транзакцию, начатую при уходе со страницы. Отправленный черновик
  удаляется вместе с отложенной записью и не воскресает после перезагрузки; черновик, который другая
  вкладка записала после этой, с другим содержимым, остаётся.
- Новая попытка отправки записывается (strict durability) до первого запроса. Если хранилище отказало
  или не ответило за 3 с, сообщение всё равно уходит, но плашка и уведомление говорят, что после
  перезагрузки повтор небезопасен (ответивший позже `IndexedDB` всё же следит за попыткой). После
  перезагрузки попытка — «результат неизвестен», сама не отправляется; повтор — тот же ключ и копия, а
  отказ (4xx) на нём не считается доказательством, что сообщение не сохранено: первый запрос мог уйти.
  Тот же текст с тем же файлом (имя, тип, размер, дата) после перезагрузки — та же попытка. Пока идёт
  отправка, `beforeunload` помечает уход со страницы: Firefox и WebKit обрывают запросы раньше
  `pagehide`, и попытка после перезагрузки говорит, что страница обновилась. Безопасный повтор держится,
  пока сервер хранит ключ — пока жива его запись (для архивных диалогов — `archive_retention_days`);
  попытка старше суток показывается с предупреждением.
- Ошибки хранилища (нет IndexedDB, запрет, квота, повреждённая запись, нет ответа) не стирают работу: о
  них говорит уведомление; файл, который не удалось сохранить, называется, чтобы прикрепить его снова.
  Открытие базы ждёт до 3 с, оператор ждёт хранилище (открытие диалога, отправка, выход) тоже до 3 с.
- Две вкладки: черновик — последняя запись побеждает, а вкладка, перезаписавшая чужую правку (текст или
  файл), говорит об этом; чужая неразрешённая попытка не перезаписывается, а подхватывается.
- Явный «Выйти» спрашивает, если в браузере есть черновики или отправки аккаунта, и удаляет их и
  `sessionStorage` вкладки — и когда сессия на сервере уже кончилась (401 на выход). Истёкшая сессия
  (401, смена пароля) оставляет их тому же аккаунту; другой аккаунт их не видит.

## UI-примитивы

- Нативные `button`, `input`, `textarea`, `form` и `label` остаются нативными, оформление — в
  `styles/app.css`. Обёртка в `components/ui/` нужна, когда повторяется поведение, а не разметка.
- Составные контролы — на Reka UI: она даёт клавиатуру, фокус и ARIA. Подписи кнопок-иконок —
  Tooltip (`ui/IconButton`); окна — Dialog (`ui/ModalDialog`, просмотр фото); выбор проекта и папки
  диалога — DropdownMenu с RadioGroup (`ui/MenuSelect`); вкладки папок — Tabs; список диалогов — Listbox
  (одна остановка Tab, стрелки, Home/End, поиск по буквам). Готовые ответы — свой лёгкий список при поле
  ответа: фокус остаётся в поле, активный вариант — `aria-activedescendant`. В окне каталога ответов
  (`composer/ReplyCatalog`) группы — Listbox, действия группы и ответа — `ui/ActionMenu`.
  Подтверждения — AlertDialog (`ui/ConfirmDialog`), вкладки проекта — Tabs. Поиск сотрудника — Combobox
  (`staff/StaffPicker`) без `ComboboxViewport`: список ищет на сервере или в загруженном списке, первый
  ответ подсвечен.
- Окна администрирования загружаются отдельными чанками только при открытии: у операторов их кода
  нет в основном бандле. Если чанк не загрузился (старая вкладка после обновления), окно закрывается
  с уведомлением, а рабочее место и черновики остаются: экран «Не удалось загрузить панель» в
  `main.ts` показывается только до старта приложения.
- Окно, открытое из меню, открывается после того, как меню вернуло фокус на свою кнопку: Reka
  возвращает его только по таймеру, и раньше открытое окно запомнило бы исчезающий пункт меню.
- Listbox Reka сам переводит фокус на значение, выбранное из кода (новая группа каталога, группа из
  результатов поиска), через несколько микрозадач после отрисовки. Фокус после такого выбора ставится
  следующей задачей (`setTimeout`), иначе Listbox заберёт его себе.
- В reka-ui 2.11.0 Tooltip вокруг DropdownMenuTrigger (и наоборот) лишает меню опорного элемента:
  у кнопки меню «Управление» на узком экране подпись — свой скрытый элемент, показанный CSS.
- Кнопка, которая ждёт ответа сервера, получает `aria-disabled="true"` и игнорирует повторное нажатие:
  атрибут `disabled` сбросил бы фокус клавиатуры.
- Кнопки-иконки (`ui/IconButton`), закрытие окон, «⋯», кнопки выбора из списка, шапки и поля ответа — области
  нажатия не меньше 44×44 при любом указателе (на touch 48×48 там, где есть место). Иконка остаётся своего размера;
  где 44 px сдвинули бы раскладку, место возвращают отрицательные поля. Проверяет `e2e/target-sizes.spec.ts`.
- Когда один экран сменяет другой, фокус переходит на его заголовок или первое поле.
- Поведение проверяют `e2e/a11y.spec.ts`, `e2e/operator.spec.ts`, `e2e/catalog.spec.ts`, `e2e/admin.spec.ts`
  и `e2e/passwords.spec.ts` на production-сборке под CSP панели:
  клавиатура (Tab, Enter, пробел, Esc, стрелки), фокус, роли и имена для скринридера, отсутствие нарушений
  CSP и ошибок в консоли. API в них отвечает `e2e/stub/api.mjs` — те же пути и формы ответов, что у
  backend, с дельтами по ревизиям, курсором истории, ревизиями папок и потоком событий; маршруты
  установки (аккаунты, пароли, проекты, участники, подключения, логотипы) — `e2e/stub/admin.mjs` с теми
  же правами, правилами и ответами, что у backend.

## Ограничения

- CSP панели не ослабляется (`src/resolvate/console.py`): `script-src 'self'`, `style-src 'self'`, без
  `unsafe-inline`, `data:` и `blob:`. Статические атрибуты `style="…"` в шаблонах, `v-html`, блоки
  `<style>` в компонентах и строковые `:style` запрещены тестом `src/templates.test.ts`. Динамический
  `:style` объектом допустим: Vue применяет его через CSSOM.
- Компоненты Reka UI, которые вставляют `<style>` (в reka-ui 2.11.0 — viewport у Select, Combobox и
  ScrollArea, а также `Viewport`), не используются: CSP их блокирует, а ослаблять её ради оформления
  нельзя (`docs/DESIGN.md`).
- Тема применяется скриптом `src/boot/theme-boot.js` до первой отрисовки, для экрана входа и панели
  одинаково. Ключ `localStorage` — `resolvate.theme` (сохранённые настройки совместимы).
- Минимальные браузеры (Tailwind CSS 4): Safari 16.4, Chrome 111, Firefox 128.

Браузерные тесты локально удобнее запускать в образе `mcr.microsoft.com/playwright:v1.63.0-noble`:
он уже содержит Chromium, Firefox и WebKit.
