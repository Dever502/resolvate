# Разработка консоли

Vue 3 + TypeScript + Pinia + Reka UI, Vite и Tailwind CSS 4.
Пользовательские возможности и ограничения — в [руководстве оператора](../docs/CONSOLE.md),
визуальные правила — в [DESIGN.md](../docs/DESIGN.md). Здесь — запуск, устройство и контракты,
которые важно сохранить при изменениях.

## Быстрый старт

Нужен Node.js 24. Команды из каталога `frontend/`:

```bash
npm ci --ignore-scripts
npm run dev
```

Vite открывает панель на `http://localhost:5173/` и проксирует `/console/*` на
`http://localhost:8080`. На backend нужен `CONSOLE_ORIGIN=http://localhost:8080`;
dev-прокси подставляет этот Origin в запросы. Это режим разработки, не production-конфигурация.
Без работающего backend интерфейс можно проверять через тестовую заглушку Playwright.

```bash
npm run build
```

Сборка попадает в `../src/resolvate/console_dist/` (не коммитится).
Production-приложение отдаёт её на `/console/`; Docker собирает её автоматически.
При отсутствии сборки маршрут панели отвечает 503, остальные API продолжают работать.

## Проверки

```bash
npm run check:lockfile
npm run typecheck
npm test -- --maxWorkers=2
npm run build
npx playwright install --with-deps chromium firefox webkit
npx playwright test --project=chromium
npx playwright test --project=firefox
npx playwright test --project=webkit
```

`npm run check` объединяет lockfile, typecheck, unit-тесты и сборку, включая проверку
CSP-безопасной разметки и лицензий. Для ноутбука команды выше позволяют ограничить unit workers.
Браузерные тесты запускайте последовательно: у каждого stub-сервера общее состояние,
поэтому `workers: 1` — требование корректности, а не настройка скорости.
Независимые процессы возможны только с разными `STUB_PORT` и каталогами результатов.

Playwright использует production-сборку и `e2e/stub/`, без живого Telegram и серверных данных.
После правки исходников сначала пересоберите панель. Тесты с фикстурой `consoleErrors`
проверяют также ошибки браузера и нарушения CSP. WebKit не заменяет ручную проверку Safari/iOS;
проверяются движки закреплённой версии Playwright, а не все старые версии браузеров.

### Как проверять асинхронный UI

- Ждите наблюдаемой готовности: выбранного проекта, доступного Composer, принятого файла,
  окончания конкретного запроса. Исчезнувшее превью ещё не означает, что следующий черновик прочитан.
- `setInputFiles()` напрямую меняет скрытый input и обходит видимую кнопку. Перед загрузкой
  дождитесь `toBeEditable()` поля ответа или `toBeEnabled()` кнопки прикрепления;
  после загрузки подтвердите появление файла, прежде чем менять диалог.
- Цвет и геометрию после CSS-перехода проверяйте через `expect.poll` или завершение анимации,
  не мгновенным чтением и не произвольным `waitForTimeout`.
- Для гонок удерживайте конкретный ответ API или транзакцию IndexedDB. Повторные прогоны полезны,
  но не заменяют управляемое воспроизведение.
- Не исправляйте падение ослаблением assertions или включением retries без выяснения причины.

Точечный запуск и просмотр сохранённого trace:

```bash
npx playwright test e2e/attachments.spec.ts --project=chromium --repeat-each=3
npx playwright show-trace 'test-results/<failed-test>/trace.zip'
```

В CI trace находится в artifact упавшего browser job. Сначала сверяйте SHA и имя теста.
Состав CI и границы проверок — в [TECHNICAL.md](../docs/TECHNICAL.md#разработка-и-проверки).

### Интеграция с настоящим backend

Нужны Python dev-зависимости в `.venv` корня репозитория, собранная консоль и **отдельный
одноразовый PostgreSQL-кластер**. Тестовая роль должна создавать БД и роли; рабочую БД не используйте.

```bash
export TEST_POSTGRES_DATABASE_URL='postgresql+asyncpg://resolvate_test:resolvate-test-only-password@127.0.0.1:5432/resolvate_test'
export ALLOW_POSTGRES_TEST_DATABASE_CREATION=yes
npx playwright test --config=playwright.integration.config.ts
```

Сервер на `127.0.0.1:4174` (`CONSOLE_TEST_PORT` меняет порт) создаёт и удаляет собственные
БД, роли и файлы. Production `.env` не читается; runtime работает без SUPERUSER/BYPASSRLS.
Проверяются настоящие HTTP, cookie/CSRF, права, отправка в очередь, история после reload,
аккаунты, проекты и multipart-вложение. Telegram polling, внешние интеграции и фоновые доставки
здесь не запускаются: тест не доказывает фактическую доставку клиенту.

| UI по доменам | `components/auth,workspace,projects,staff,tickets,folders,chat,composer,account/` |

Пути в таблице относительны `frontend/src/`.
Компоненты используют stores, не дублируют бизнес-правила. Новый store или общий примитив нужен
для повторяемого состояния/поведения, а не для одного локального переключателя.

## Контракт ответа и вложений

`Draft` содержит текст и до пяти файлов в порядке добавления. Выбор, drop и paste идут через
`chat.attach()` и правила `lib/attachment.ts`. Лимит — 20 MiB на файл, 3900 символов без файла,
800 с файлом; UI считает Unicode-символы как сервер. Backend принимает один файл на запрос.
Неподдерживаемые, пустые, слишком большие и лишние файлы называются с причиной отказа;
уже прикреплённые файлы и текст сохраняются.

- Фото декодируется через `createImageBitmap` в canvas без `blob:`/`data:` URL.
  Bitmap освобождается; видео, PDF и аудио показывают карточку, кадр видео не извлекается.
- Вставка файлов работает только при отсутствии текста в буфере. Обычный текст и ссылки
  остаются обычной вставкой. Drop принимает панель открытого диалога, не весь viewport.
- Пока черновик читается, идёт отправка или поверх диалога открыто окно, недопустимые
  способы прикрепления блокируются; перетаскивание объясняет отказ.
- Enter отправляет, Shift+Enter добавляет строку, IME-подтверждение не отправляет.
  Смена проекта/диалога во время отправки запрещена.

Каждый файл уходит отдельной неизменяемой `SendAttempt` со своим `X-Idempotency-Key`.
Текст — подпись первого файла. Это последовательность сообщений, не атомарный пакет и не альбом.

| Исход попытки | Поведение |
| --- | --- |
| 2xx | Удалить принятый файл и неизменённый текст из черновика; статус доставки смотреть в истории |
| Подтверждённый 4xx первого запроса | Завершить попытку, сохранить черновик для исправления |
| Обрыв, дедлайн, 5xx | Сохранить неизвестную попытку; повторить только её исходные данные с тем же ключом |
| Отказ на повторном запросе | Не считать доказательством, что первый запрос не был принят |
| Принято сервером, но не записана локальная очистка | Остановить очередь, сохранить исходную попытку; повторить очистку до следующего файла |

Попытка закрывается также по её ключу `command` в истории. Ошибка обновления истории не отменяет
принятое сообщение. Следующий файл начинается только после сохранения очищенного черновика;
попытка удаляется после этой записи. `draftFileId` различает даже одинаковые файлы.
Кнопка «Остановить» прекращает очередь после текущего файла; уже принятое не отзывается.
Безопасный повтор ограничен сроком хранения серверного ключа; старые попытки получают предупреждение.

## Локальное сохранение и сессия

- IndexedDB `resolvate-work`: `drafts`, `draftFiles`, `attempts`; ключ — аккаунт/проект/диалог.
  Байты файлов — ArrayBuffer для совместимости с WebKit. Серверная история, пароли и API-токены
  туда не копируются, но сами черновики могут содержать чувствительные данные.
- Текст сохраняется с задержкой 300 мс, файлы — сразу. Записи одного черновика упорядочены;
  перед чтением завершаются предшествующие записи. На `pagehide` несохранённый текст дополнительно
  попадает в `resolvate.unsaved`; запись не должна возвращать уже отправленный черновик.
- `sessionStorage` помнит место вкладки. Прямая ссылка с проектом/тикетом обрабатывается один раз.
  Истёкшая сессия оставляет работу тому же аккаунту, другой аккаунт её не видит.
- Явный выход подтверждает удаление локальной работы, в том числе если сервер уже вернул 401.
  Смена пароля завершает сессии. Ошибка выхода не должна принудительно разлогинивать.
- `session.loggingOut` и общий Promise защищают от повторного logout после размонтирования меню.
  Ответы старой сессии не изменяют новую. При закрытии мобильного меню ошибка выхода остаётся
  в уведомлении рабочей области.
- Отказ или таймаут IndexedDB сопровождается предупреждением, не обещанием сохранности.
  Новая попытка записывается до запроса; после reload она неизвестна и сама не отправляется.
  Две вкладки предупреждают о перезаписанной правке, чужая неразрешённая попытка не затирается.

## Навигация, история и фокус

Мобильная компоновка описана в [DESIGN.md](../docs/DESIGN.md#общие-правила).
`AccountMenu` рендерится в одном экземпляре. Reka отвечает за Tab, Esc и возврат фокуса;
переход к проекту по стрелкам/Home/End
выполняется на keydown: отложенный выбор Reka 2.11 может пропустить быстрое отпускание клавиши.

Для [готовых ответов](../docs/CONSOLE.md#готовые-ответы-и-личное-меню) сохраняйте выделение
Composer до вставки и возвращайте фокус к источнику открытия по Esc. Конфликт revision
в каталоге не должен затирать несохранённый текст.

`MessageList` помечает прочитанным только актуальное последнее сообщение в видимой панели
и видимой вкладке. После подтверждения отметки обновляется счётчик списка.
Новые сообщения при чтении выше не считаются прочитанными; двойной клик по открытому диалогу
переходит вниз без повторной загрузки и потери черновика.
Размеры рамок фото/видео известны заранее, `ResizeObserver` сохраняет положение чтения
при поздней загрузке медиа, изменении ширины и высоты Composer.

Окна из меню открываются после его закрытия и возврата фокуса. Окна администрирования
загружаются отдельными чанками; ошибка загрузки закрывает окно с сообщением, не рабочее место.
Следите за отложенным фокусом Reka: выбранный из кода Listbox и закрывающийся DropdownMenu
могут перенести его после вашей синхронной обработки.

## CSP и оформление

- CSP задаёт backend в `src/resolvate/console.py`: без `unsafe-inline`, `data:`, `blob:` и CDN.
  Не добавляйте `v-html`, блоки `<style>`, статические inline-стили или строковые `:style`.
  Динамический объект `:style` допустим через CSSOM. Проверка — `src/templates.test.ts`.
- Не используйте primitives Reka, вставляющие `<style>` (например, viewport Select/ScrollArea),
  ради них нельзя ослаблять CSP. Проверяйте поведение установленной версии в браузере.
- Тема применяется до первого paint; ключ `resolvate.theme` общий для входа и рабочего места.
  System следует `prefers-color-scheme`. Интерактивные цвета зависят от поверхности, не только темы.
- Размеры контролов и матрица визуальных проверок — в [DESIGN.md](../docs/DESIGN.md).
- Снимки экрана дополняют assertions, но не заменяют проверки поведения. В WebKit их сохранение
  может быть пропущено из-за вставки стиля самим Playwright; CSP и сценарий при этом проверяются.
