# Resolvate

Resolvate — многопроектная система поддержки: клиенты пишут Telegram-боту или через backend
сайта, операторы отвечают в веб-панели и темах закрытой Telegram Forum-группы.
Переписка, права и каталог готовых ответов хранятся в PostgreSQL.

Документация описывает код **этой версии репозитория**. Версия Python-пакета — `4.0.0`;
образ с тегом `v4.0.0` не равнозначен последнему `main`. Для развёртывания выбирайте образ
и файлы репозитория одного проверенного коммита.

## Возможности

- Изолированные проекты со своими ботами, Forum-группами, операторами и интеграциями.
- Веб-панель `/console/`: переписка, поиск, папки, карточка клиента, оценки и готовые ответы.
  Адаптивный интерфейс, клавиатурная навигация, светлая, тёмная и системная темы.
- Текст, JPEG/PNG/WebP, MP4/MOV, PDF и голосовые OGG/Opus до 20 MiB.
  В панели — до пяти файлов за отправку, перетаскивание, вставка и локальные черновики.
- Общий каталог готовых ответов: редактирование в Web, копируемые публикации в Telegram.
- Управление проектами, сотрудниками, правами, паролями и логотипами из панели.
- Отдельные Web Support API для backend сайта и Operator API для автоматизации.
- Remnawave 2.8.x: информация о подписке, продление, перевыпуск ссылки/ключей,
  сброс устройств и сверка неопределённых результатов.
- Очереди доставки с восстановлением после перезапуска, подписанный notification webhook,
  ротация тем и очистка архивов, метрики и резервное копирование.

## Как устроена установка

```text
Telegram-клиент → бот ────────┐
                             ├→ Resolvate + PostgreSQL + медиа
Backend сайта → Web API ──────┘            ↕
                               Web-панель / Forum-темы / Operator API
```

На идентичность клиента в канале проекта приходится один постоянный тикет.
После закрытия новое обращение открывает следующий цикл того же тикета;
физическая Telegram-тема может меняться при ротации. Telegram- и Web-клиенты автоматически
не объединяются. Backend — источник истины, Web — полный интерфейс, Telegram — упрощённый
операторский интерфейс, а не отдельная система данных.

## Запуск

Нужны Linux, Docker Engine, Docker Compose v2+ и HTTPS reverse proxy.
Каждому рабочему проекту нужны отдельный бот и приватная supergroup с Topics.
Поддерживается один экземпляр приложения и PostgreSQL 16.

1. Подготовьте рабочую копию и конфигурацию:

   ```bash
   git clone https://github.com/Dever502/resolvate.git
   cd resolvate
   cp .env.example .env
   chmod 600 .env
   ```

2. В `.env` задайте `CONSOLE_ORIGIN=https://support.example.com` и три разных случайных
   URL-safe пароля длиной от 16 символов: `POSTGRES_ADMIN_PASSWORD`,
   `POSTGRES_MIGRATION_PASSWORD`, `POSTGRES_RUNTIME_PASSWORD`.
   Ботов, группы и интеграции настраивают позже в панели.

3. Выберите **опубликованный после успешного push-CI** образ. Замените `<commit-sha>`
   полным SHA нужного коммита; рабочая копия должна соответствовать ему:

   ```bash
   export DEPLOY_DIR="$PWD"
   sh scripts/deploy.sh deploy 'ghcr.io/dever502/resolvate:<commit-sha>'
   sh scripts/production-compose.sh ps
   sh scripts/production-compose.sh exec resolvate python -m resolvate.console_admin admin --name "Администратор"
   ```

   Скрипт закрепляет digest, проверяет конфигурацию, выполняет provisioning и миграции,
   ждёт healthcheck и сохраняет `deployment.env` для последующих команд.
   CLI запрашивает пароль администратора интерактивно и используется один раз.

4. Настройте [HTTPS reverse proxy](deploy/nginx/resolvate-api.conf.example).
   Откройте `https://support.example.com/console/`, создайте проект, настройте его бота
   и группу, выдайте доступ операторам и включите проект.

Проверки, доверенные прокси, обновление и восстановление — в [руководстве по эксплуатации](docs/OPERATIONS.md).
При новом входе в shell снова задавайте `DEPLOY_DIR`, если установка не в `/opt/resolvate`.
Образы поставляются через GHCR; отдельный релизный пакет в PyPI не публикуется.

Альтернатива для разового запуска — `./scripts/start.sh IMAGE`. Без аргумента и `APP_IMAGE`
он выбирает `v4.0.0`. Этот скрипт **не создаёт `deployment.env`** для
`production-compose.sh` и rollback; для обслуживаемой установки используйте `deploy.sh`.

## Что важно знать до запуска

- Новая установка — PostgreSQL с чистой многопроектной схемой. Автоматического переноса
  однопроектной БД 3.x нет; обычные обновления 4.x выполняются миграциями без пересоздания БД.
- Принятие ответа сервером не означает доставку клиенту. Telegram-доставка — at-least-once:
  редкий дубль после сбоя возможен; exactly-once не обещается.
- Черновики хранятся в браузере, не синхронизируются между устройствами и удаляются при явном выходе.
- Проверка вложений ограничивает форматы и ресурсы, но не заменяет антивирус и изоляцию декодеров.
- Web API предназначен для backend сайта: не передавайте ключ в браузер.
  Аудит Web-операций в БД содержит email и тексты сообщений; защищайте БД, её выгрузки и резервные копии.
- Кластерный режим, автоматическое переключение на резервный сервер и сборка подписки
  из нескольких Remnawave-панелей не реализованы.
