# UX release regression консоли Resolvate — 2026-10-26

Регрессионный проход после цепочки UX-стабилизации (#47–#53) и финальной полировки (PR `polish/final-ui-pass`). Проверяет, что найденное аудитом 2026-10-25 закрыто, а остальное не сломано.

Production-код в этом PR не менялся. Что добавлено:
- тест раскладки по всем ширинам;
- обновлённый интеграционный тест команд (контракт сменился в #50, см. Known Issues);
- этот отчёт.

## Executive Summary

- **Все 13 находок аудита закрыты.** В одной (№ 11) часть рекомендации отклонена осознанно: macOS-сглаживание шрифта (Mac для проверки нет).
- **Регрессий продукта цепочка не внесла.** Одна регрессия тестового контракта найдена и исправлена: интеграционный тест на реальном API падал с #50 (Known Issues, п. 2).
- **Раскладка.** Проверена на 8 ширинах в двух темах и трёх движках: без переполнения, наложений, контролов за краем экрана, «прыжков» шапки, поля ответа и истории.
- **Флейк WebKit `mobile-workspace.spec.ts:132` («drawer backdrop with touch») — не флейк и не гонка.** Он падает детерминированно (все 6 touch-прогонов падают, все 6 mouse-прогонов проходят) и так же падает на `main` в плановом CI без наших изменений. Тест не скрыт, не пропущен и не ослаблен: он остаётся красным, проблема записана.
- **Вердикт: Ready with caveats.** Оговорки — в разделе Release Verdict.

## Known Issues

### 1. WebKit: тап по подложке не закрывает мобильное меню

- **Тест:** `e2e/mobile-workspace.spec.ts:132`, «drawer backdrop with touch», на 320 и 375 px.
- **Воспроизводимость:** детерминированная, а не флейк.
  - локально `--repeat-each=3`: 6 из 6 touch-прогонов падают, 6 из 6 mouse проходят;
  - на `c19e675` (первый PR цепочки, консоль ещё как в `main`) тест падал так же — 6 из 12 прогонов тогда же, с `--repeat-each=3`;
  - плановый CI `main` @ `58d78d4` ([run 40297471795](https://github.com/Dever502/resolvate/actions/runs/40297471795), job «Console webkit»), без наших изменений: падают эти же два теста.
- **Причина.** Установлена пробой событий в трёх движках:
  1. Подложка Reka (`DialogOverlayImpl`) вешает `@pointerdown.left.self.prevent`: у `pointerdown` по подложке `defaultPrevented = true`.
  2. Для touch Reka не закрывает слой на `pointerdown`, а ждёт следующий `click` на документе (`DismissableLayer/utils.js`, ветка `pointerType === "touch"`). Для мыши закрывает сразу, поэтому mouse-тесты проходят.
  3. После отменённого `pointerdown` Chromium и Firefox присылают `click` (так требует Pointer Events), а WebKit в Playwright — нет. Там последовательность обрывается на `pointerdown → touchstart → pointerup → touchend`.
  4. Тап по обычной кнопке в том же WebKit даёт `click` — эмуляция touch в целом работает.
  5. Не помогли: `cursor: pointer` и обработчик `click` на подложке или её родителе, снятие `pointer-events: none` с `body`.
- **Не гонка синхронизации.** Тест ждёт окончания анимации открытия, а Reka вешает свой слушатель через `setTimeout(0)`. Тап доходит до подложки (`pointerdown` с `target = .dialog-backdrop`), но `click` не приходит вовсе, сколько ни жди. Поправить «синхронизацию» в тесте нечем, поэтому тест не менялся.
- **Влияние.** Реальный iOS Safari не проверялся. Если он ведёт себя так же, тап мимо меню на iPhone его не закроет. Закрыть можно кнопкой «Закрыть меню» (44×44) или выбором пункта. Мышь, Chromium и Firefox на touch работают.
- **Почему не исправлено здесь.** Проблема существовала до цепочки и не подтверждена на устройстве. Очевидная правка — закрывать по `pointerup` для touch — рискует «призрачным» кликом по списку под подложкой: именно от него Reka и ждёт `click`. Нужна проверка на реальном iPhone, затем исправление в консоли или в Reka.

### 2. Интеграционный тест команд устарел с #50 — исправлен в этом PR

- **Что.** `frontend/integration/console.spec.ts` («commands use the project API, notes stay internal, retries do not duplicate») — единственный браузерный тест на реальном API и PostgreSQL (CI-джоб «Console with real API and PostgreSQL», запускается и на pull request). Он закреплял поведение до #50:
  - после успешной `/note` команда и её ключ остаются в поле;
  - результат показывается в `role="status"`;
  - повтор после перезагрузки идёт под тем же ключом.

  В #50 это поменялось по решению продукта: успешная команда уходит из поля, ключ удаляется, короткий результат — всплывающее уведомление в `aria-live`; повтор под тем же ключом остался только для неизвестного исхода.
- **Проверено.** Исходный тест на сборке каждого коммита:
  - на #49 (`fa78f29`) — 4 из 4;
  - на #50 (`28868f3`) — падает на `getByRole("status")`;
  - на полировке (`a6e981f`) — падает так же.
- **Последствие для CI.** Этот джоб будет красным на #50, #51, #52, #53 и PR полировки, пока не слит этот PR.
- **Исправление (только тест).** Сценарий переписан под новый контракт с тем же смыслом:
  1. первый запрос `/note` доходит до сервера (`route.fetch`), а ответ браузеру обрывается — исход неизвестен;
  2. после перезагрузки ключ и черновик на месте, Enter повторяет запрос под тем же ключом;
  3. сервер отвечает сохранённым результатом, а `/notes` на реальном backend содержит заметку ровно один раз.

  Локально: 4 из 4 на реальном API и PostgreSQL.

### 3. CI: Firefox в плановом прогоне не запускается

В том же плановом прогоне `main` job «Console firefox» падает до тестов: Firefox не стартует, потому что `$HOME` (`/github/home`) принадлежит не текущему пользователю. Playwright прямо предлагает `HOME=/root` в шаге workflow. Это инфраструктура CI, не код консоли. Локально Firefox проходит весь набор.

### 4. Мелкие недочёты, которые были до цепочки

- **Шапка готовых ответов прыгает при загрузке.** Попап `#` привязан к низу и растёт вверх, когда приходят группы: шапка с кнопкой закрытия поднимается на 54 px (замерено, 1280 px) примерно через 180 мс после открытия (задержка поиска плюс запрос). Клик по «×» ровно в этот момент может промахнуться. Так было и до цепочки. Тест полировки ждёт загрузки списка, прежде чем нажимать.
- **Enter до загрузки списка команд.** Если нажать Enter на `/note …` сразу после перезагрузки, пока список команд проекта грузится, консоль ответит «Неизвестная или недоступная команда.», хотя команда есть. Запрос не отправляется, повтор через мгновение работает. Строка та же на `main` (`58d78d4`).

### 5. Прочее

- **`tabular-nums` у счётчика без видимого эффекта.** В текущем шрифте цифры уже равной ширины; свойство закрепляет это на случай смены шрифта.
- **`text-wrap: pretty` поддерживается не везде.** Chromium 153 и WebKit 26.6 — да, Firefox 155 — нет (`CSS.supports`). Где поддержки нет, свойство игнорируется без последствий. `balance` поддерживают все три.
- **Пока шторка уезжает (120 мс), подложка принимает клики.** Это модальный слой Reka: `body` без `pointer-events` до размонтирования.

## Accessibility (DOM/ARIA)

Проверено только по DOM, ролям, именам и фокусу в Playwright. **Реальный скринридер (VoiceOver, NVDA, TalkBack) не использовался.**

Проверено:
- **Мобильное меню.** Диалог «Resolvate»: фокус внутри и возвращается на кнопку меню после Esc, кнопки «Закрыть меню» и подложки, в том числе после анимации выхода. После закрытия `body` снова принимает указатель.
- **Готовые ответы.** Поле поиска — `combobox` с `aria-activedescendant`. Кнопка-иконка «Закрыть готовые ответы» сохранила имя. После закрытия фокус в поле ответа.
- **Команды.**
  - ошибки и неизвестный исход — `role="alert"`;
  - результат — в постоянной области `aria-live="polite"`, без второго `role="status"` на странице;
  - подтверждения — `alertdialog` с именем и описанием; `/closeall` — ввод названия проекта.
- **Заметки.** Текстовая подпись «Внутренняя заметка» и значок, а не только цвет. В forced-colors различимы.
- **Папка.** Кнопка «Папка диалога: <имя>». Имя папки в мета-строке скрыто от скринридера (`aria-hidden`), чтобы не звучать дважды.
- **Карточка клиента.** Список `dl`; «Закрыть карточку» возвращает фокус на имя клиента.
- **Общие контракты.** Контраст интерактивных цветов по WCAG — по вычисленным цветам (`interactive-colors.spec.ts`), области нажатия 44×44 (`target-sizes.spec.ts`), порядок Tab и клавиши (`a11y.spec.ts`).

Не проверено:
- как всё это звучит в реальном скринридере: порядок, формулировки, повторы объявлений;
- навигация по ротору VoiceOver и в режиме просмотра NVDA.
