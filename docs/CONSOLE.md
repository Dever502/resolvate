# Панель операторов

Панель доступна по `/console/` в том же приложении и на том же порту, что и API.
Клиенты по-прежнему пишут Telegram-боту или через API своего сайта.

## Включение

1. Подготовьте чистую PostgreSQL и выполните миграции штатным способом. Миграция проектов
   отказывается изменять заполненную однопроектную БД: автоматического переноса нет.
2. Укажите в `.env` `CONSOLE_ORIGIN=https://support.example.com` — точный внешний origin,
   без `/console` и других путей. Параметр обязателен для запуска установки. Для локальной разработки
   допустим `http://localhost:8080`. Compose уже передаёт этот параметр через `env_file`.
3. Перезапустите приложение и настройте HTTPS reverse proxy на его API-порт. Не публикуйте
   внутренний порт напрямую; пример конфигурации находится в `deploy/nginx/`.
4. Создайте первого администратора внутри запущенного контейнера:

   ```bash
   sh scripts/production-compose.sh exec resolvate python -m resolvate.console_admin admin --name "Администратор"
   ```

   Пароль запрашивается дважды интерактивно (12–128 символов), не передаётся в аргументах.
   При прямом запуске используйте `python -m resolvate.console_admin admin` в окружении приложения.
   CLI создаёт только первого администратора установки, повторная инициализация запрещена.
5. Откройте `https://support.example.com/console/`. Другие аккаунты создаются администратором
   через «Аккаунты». Открытой регистрации и обязательной привязки к Telegram ID нет.
6. В «Проекты» создайте проект и укажите логин его единственного администратора.
   Администратор проекта настраивает бота и приватную Forum-группу во вкладке «Подключения».
   После настройки администратор установки включает проект. Проектные ключи в `.env` не нужны.

Operator API и Web API включаются отдельно в подключениях проекта; cookie не дают доступ к этим API,
а их токены не заменяют вход в панель. Сессия действует 12 часов. Отключение аккаунта отзывает
его сессии; последнего активного администратора отключить нельзя.

## Проекты и права

- Единственный администратор установки управляет аккаунтами, созданием/отключением проектов
  и передачей администрирования. Доступ к переписке не возникает автоматически; кнопка
  «Выдать себе доступ» явно добавляет его оператором и оставляет запись в журнале доступа.
- Единственный администратор проекта настраивает его подключения и добавляет/удаляет операторов
  по точному логину. Он не видит общий список аккаунтов и чужие проекты, не назначает администраторов.
- Оператор отвечает клиентам и работает с готовыми ответами только доступных проектов.
  Один аккаунт может иметь разные роли в разных проектах. Регистрация аккаунта сама по себе
  доступа не даёт. Отзыв доступа к одному проекту не затрагивает остальные.
- Передача администрирования атомарна. Прежний администратор проекта теряет доступ к нему;
  при необходимости его отдельно добавляют оператором. Аккаунт, управляющий проектом,
  нельзя отключить до передачи управления. Отключение проекта не удаляет его данные.
- Количество проектов не ограничивается искусственно. Установка остаётся single-instance;
  ресурсы сервера общие, логическая изоляция не равнозначна отдельным виртуальным машинам.
- Для работы через Telegram у аккаунта должен быть указан Telegram ID, а у аккаунта — доступ
  к проекту. Членство в группе само по себе не разрешает команды. Само чтение Telegram-группы
  контролирует Telegram: администратор проекта обязан держать её приватной и удалять из неё
  пользователей при отзыве доступа. Уже полученные сообщения отозвать невозможно.

В панели переключатель показывает только активные проекты с выданным доступом. При переключении
очищаются текущая переписка, вложение и черновик; незавершённая отправка временно блокирует переключение.
Ключи интеграций не возвращаются в браузер: видно только, настроен ли ключ. Пустое поле сохраняет
старый ключ. Токен бота и ID группы можно сохранить по очереди, в любом порядке; включить проект
можно только после заполнения обоих полей. Бот и группа закрепляются независимо при сохранении;
для другого канала создайте новый проект. Обновить токен того же бота можно.
API-ключи не могут повторяться между проектами. Интеграции доступны только по публичному HTTPS;
локальная сеть, loopback и служебные адреса заблокированы, DNS проверяется при каждом обращении.

Адрес API проекта: `/projects/<project-id>/api/v1/...`; остальные части контрактов не изменились.
Общие адреса `/api/v1/...` без проекта в установке недоступны. Идентификатор виден в «Подключениях».

При потере доступа к администратору установки выполните на сервере:

```bash
python -m resolvate.console_admin existing-login --recover
```

Команда интерактивно задаёт новый пароль существующему аккаунту и передаёт ему управление.
Сессии прежнего и нового администратора отзываются; восстановление записывается в журнальную
таблицу `access_audit`. Не передавайте пароль аргументом командной строки.

## Работа

- Слева — общие активные/закрытые диалоги, поиск клиента и персональные непрочитанные.
  Справа — переписка и карточка клиента. На телефоне список и переписка открываются по очереди.
- Последние 50 сообщений загружаются сразу, предыдущие — при прокрутке вверх. Обновления
  проверяются каждые 3 секунды, неизменившиеся сообщения повторно не передаются.
- `/` открывает общие готовые ответы; продолжение ввода фильтрует их. Выбор вставляет текст,
  но не отправляет его. Enter отправляет, Shift+Enter добавляет строку.
- Скрепка принимает одно фото, видео или PDF до 20 MiB. Текст — до 3900 символов,
  с вложением — до 800. ZIP/RAR, `.txt` и прочие вложения запрещены во всех каналах.
- Ответ из панели появляется в Telegram-топике с именем оператора. Клиенту он отправляется
  один раз через его канал; сообщения операторов из топика также видны в панели.
- «Завершить» и «Возобновить» меняют общее состояние диалога. Новое обращение клиента
  возобновляет его. Ротация Telegram-топика не удаляет историю панели сама по себе.
- При окончательной ошибке доступен повтор. При неизвестном результате вызова Telegram
  показано предупреждение: сначала проверьте переписку, автоматического слепого повтора нет.
  Статусы доставки и прочтения клиентом не показываются.

Редактирования, полученные от Telegram, обновляют сохранённую исходную запись в Web.
Уже отправленные Telegram-копии автоматически не редактируются. Ручное удаление в Telegram
не удаляет историю БД. Редактирование и удаление из самой панели пока не предусмотрены.

## Файлы и хранение

Байты находятся в отдельных каталогах проектов в томе данных, БД хранит ссылки и метаданные.
Дедупликация по SHA-256 ограничена одним проектом; чужие файлы не переиспользуются. Проверки формата,
размера и ресурсов уменьшают риски, но не заменяют антивирус и не гарантируют отсутствие
вредоносного содержимого в произвольном документе. PDF не отображается встроенным viewer.

Архивные тексты хранятся 60 дней по умолчанию; подходящие медиа сжимаются после 14 дней,
удаляются после 30 дней. Активные ссылки и незавершённые доставки защищают файлы от очистки.
История старых сообщений без надёжной связи с архивом не удаляется автоматически этой миграцией.
Резервировать нужно и PostgreSQL, и том данных. Панель не обещает бессрочную историю.
