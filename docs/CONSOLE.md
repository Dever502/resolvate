# Панель операторов

Единственная веб-панель доступна по `/console/` в том же приложении и на том же порту, что и API.
Она построена на Vue; исходники и команды разработки — в [frontend/README.md](../frontend/README.md).

## Текущее состояние

В ветке разработки прежний фронтенд удалён. Во Vue перенесён основной операторский флоу: вход
и проверка сессии, выбор проекта, список диалогов с поиском, архивом, общими папками и подгрузкой
страниц, переписка с вложениями, стикерами и просмотром фото, карточка клиента, ответы с черновиками,
вложениями и готовыми ответами, завершение и возобновление, live-обновления, ширина списка и режим
«список → диалог» на телефоне. Смена пароля, управление аккаунтами и проектами (создание, участники,
подключения, логотип, передача) ещё не перенесены. Это не функциональный эквивалент веб-панели
выпущенного `v4.0.0`.

Backend API панели сохранён, включая авторизацию, права доступа, CSRF, управление проектами,
историю, отправку сообщений, медиа, папки и события. Данные и миграции не меняются.
Уже настроенные Telegram-проекты продолжают работать. Для новой установки из этой ветки
после CLI-bootstrap пока потребуется работа с API панели; графического мастера настройки нет.

## Запуск

1. Для новой установки подготовьте PostgreSQL и выполните штатные миграции. Существующую
   многопроектную БД удалять или пересоздавать при замене фронтенда не нужно.
2. Укажите `CONSOLE_ORIGIN=https://support.example.com` в `.env`: точный внешний origin без пути.
   Для локальной разработки допустим `http://localhost:8080`.
3. Docker-образ собирает фронтенд автоматически. При запуске из исходников сначала выполните:

   ```bash
   cd frontend
   npm ci --ignore-scripts
   npm run build
   ```

   Нужен Node.js 24. Результат — `src/resolvate/console_dist/`, он включается в Python-пакет.
   Если сборки нет, `/console/` возвращает 503 с понятной причиной; API от неё не зависит.
4. Настройте HTTPS reverse proxy и запустите приложение. Пример — `deploy/nginx/`.
5. Только на новой установке создайте первого администратора:

   ```bash
   sh scripts/production-compose.sh exec resolvate python -m resolvate.console_admin admin --name "Администратор"
   ```

   Пароль запрашивается интерактивно (12–128 символов). Повторная инициализация запрещена.
6. Откройте `https://support.example.com/console/` и войдите существующим аккаунтом.

Дополнительного флага включения нет. Старый preview-адрес `/console/next/` удалён.
HTML и ответы API не кешируются; хешированные JS/CSS кешируются и выдаются с Brotli/gzip,
если это поддерживает клиент. CSP остаётся строгой, без inline-скриптов и внешних CDN.

## Сохранённые права и API

- Единственный администратор установки управляет аккаунтами и проектами. Доступ к переписке
  не возникает автоматически: нужно явное членство, выдача себе доступа аудируется.
- Единственный администратор проекта настраивает подключения и управляет операторами проекта,
  но не аккаунтами установки. Поиск кандидатов возвращает только ID, имя и логин активных
  сотрудников, до 50 результатов, без секретов и членств в других проектах.
- Оператор работает только с проектами, доступ к которым ему явно выдан. Отзыв членства
  не удаляет переписку и не влияет на остальные проекты.
- Передача администрирования атомарна; отключение проекта сохраняет его данные.
- Для Telegram нужны Telegram ID сотрудника и доступ к проекту. Членство в группе само по себе
  не даёт права отправлять ответы через бота. Чтение группы контролирует Telegram: состав
  приватной Forum-группы администратор обслуживает отдельно.

API панели использует `/console/login`, `/console/me`, `/console/logout`, `/console/accounts`
и `/console/projects`. Бизнес-запросы проекта идут на `/console/projects/<project-id>/...`.
Cookie-сессия действует 12 часов; изменяющие запросы требуют корректных Origin и `X-CSRF-Token`.
Создание аккаунтов не открыто для анонимов. Отключение аккаунта отзывает его сессии.

Web Support API и Operator API доступны по `/projects/<project-id>/api/v1/...` и используют
отдельные ключи. Cookie панели не заменяет эти ключи, ключи не заменяют вход в панель.
API-ключи сайта нельзя отдавать клиентскому браузеру.

Логотипы, пароли и настройки проектов доступны через существующие защищённые API, но пока
без соответствующих экранов. Логотипы принимаются только как PNG/JPEG/WebP до 2 MiB,
нормализуются до PNG 512×512 без метаданных; SVG и анимация запрещены.
Файлы проектов и их права изолированы, backend-проверки не зависят от наличия UI.

При потере доступа к администратору установки на сервере можно выполнить:

```bash
python -m resolvate.console_admin existing-login --recover
```

Команда задаёт новый пароль интерактивно и передаёт управление существующему аккаунту.
Сессии прежнего и нового администратора отзываются, действие записывается в `access_audit`.
Не передавайте пароли аргументами командной строки.

## История, события и хранение

История и durable-доставка между Telegram и API остаются общими. При закрытии через API панели
клиент получает то же уведомление, что при `/stop`; повторное закрытие не создаёт дубль.
События антиспама внутренние и не попадают в клиентскую историю. Оценка сохраняется одна
на цикл закрытия. Telegram-правки обновляют принятую исходную запись, не отправленные копии.

SSE `/console/projects/<project-id>/events` передаёт только сигналы обновления, без текста сообщений.
Права и сессия перепроверяются перед сигналом и каждые 10 секунд простоя. Ограничения — 4 потока
на аккаунт и 256 на установку. Прокси должен пропускать `X-Accel-Buffering: no`, а таймаут чтения
быть больше 10 секунд. Панель держит поток выбранного проекта, пока вкладка видна, и опрашивает API
каждые 3 секунды, пока поток недоступен (при открытом потоке — раз в 30 секунд).

Байты вложений находятся в отдельных каталогах проектов, БД хранит ссылки и метаданные.
Дедупликация по SHA-256 ограничена проектом. Фото-миниатюры создаются по запросу в ограниченном
процессе; кэш в памяти проекта — до 4 MiB и 64 элементов. Каждый запрос, в том числе кэшированный,
проверяет права и наличие оригинала. Приватные вложения выдаются с `Cache-Control: no-store`.
Проверки файлов не заменяют антивирус и не гарантируют безвредность произвольного документа.

Архивные тексты хранятся 60 дней по умолчанию; подходящие медиа сжимаются после 14 дней,
удаляются после 30. Активные ссылки и незавершённые доставки защищают файлы от очистки.
Резервировать нужно PostgreSQL и том данных; бессрочное хранение истории не обещается.
